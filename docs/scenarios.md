# Пользовательские сценарии модуля «Сервис задач»

## Роли пользователей

| Роль 		   | Описание 									 |
|------------------|-----------------------------------------------------------------------------|
| **Пользователь** | Студент, который создаёт задачи, меняет их статус, ищет и просматривает     |
| **Система** 	   | Модуль «Сервис задач», который выполняет операции и сохраняет данные в JSON |

## Приоритеты сценариев

- **Критический** — без сценария модуль теряет смысл
- **Важный** — нужен большинству пользователей
- **Дополнительный** — улучшает удобство, но не обязателен

## Сценарии

### Критические (без них модуль теряет смысл)

#### Сценарий 1: Создание задачи
- **Цель:** пользователь хочет добавить новую задачу.
- **Условия:** файл `tasks.json` существует или может быть создан.
- **Шаги:**
  1. Пользователь вызывает операцию `createTask(title, description)`.
  2. Система генерирует уникальный `id`.
  3. Система сохраняет задачу в память и в `tasks.json`.
- **Результат:** Задача создана, присутствует в списке, файл обновлён.
- **Приоритет:** критический

#### Сценарий 2: Просмотр списка задач
- **Цель:** увидеть все текущие задачи.
- **Шаги:** пользователь вызывает `getAllTasks()`.
- **Результат:** система возвращает массив задач.
- **Приоритет:** критический

#### Сценарий 3: Изменение статуса
- **Цель:** перевести задачу из `todo` в `in_progress` или `done`.
- **Шаги:**
  1. Вызов `updateStatus(taskId, newStatus)` с допустимым статусом.
- **Результат:** статус задачи изменён, файл обновлён.
- **Приоритет:** критический

#### Сценарий 4: Загрузка задач из файла при старте
- **Цель:** восстановить данные после перезапуска.
- **Условия:** `tasks.json` корректен.
- **Результат:** задачи загружены и доступны.
- **Приоритет:** критический

---

### Важные (нужны большинству пользователей)

#### Сценарий 5: Поиск по ключевому слову
- **Шаги:** вызов `findByKeyword("тетрадь")`.
- **Результат:** задачи с "тетрадь" в названии или описании без учёта регистра.
- **Приоритет:** важный

#### Сценарий 6: Фильтрация по статусу
- **Шаги:** `getTasksByStatus("todo")`.
- **Результат:** только задачи со статусом `todo`.
- **Приоритет:** важный

#### Сценарий 7: Отсутствие файла при старте
- **Шаги:** `tasks.json` не существует → запуск модуля.
- **Результат:** система работает с пустым списком, ошибок нет.
- **Приоритет:** важный

---

### Ошибочные / альтернативные

#### Сценарий 8: Попытка создать задачу с пустым названием
- **Шаги:** `createTask("", "описание")`.
- **Результат:** ошибка "Title cannot be empty", задача не создана.
- **Приоритет:** важный

#### Сценарий 9: Недопустимый статус
- **Шаги:** `updateStatus(1, "archived")`.
- **Результат:** ошибка "Invalid status. Allowed: todo, in_progress, done".
- **Приоритет:** важный

#### Сценарий 10: Изменение статуса несуществующей задачи
- **Шаги:** `updateStatus(999, "done")`.
- **Результат:** ошибка "Task with id 999 not found".
- **Приоритет:** важный

#### Сценарий 11: Повреждённый файл JSON
- **Условия:** `tasks.json` содержит `{invalid: json`.
- **Результат:** ошибка загрузки, при этом модуль стартует с пустым списком.
- **Приоритет:** важный

---

### Дополнительные

#### Сценарий 12: Поиск по пустому ключевому слову
- **Шаги:** `findByKeyword("")`.
- **Результат:** возвращаются все задачи (или пустой список).
- **Приоритет:** дополнительный

## Проверяемость

### Сценарий 1 (создание задачи)
1. **Что произойдёт, если при создании задачи описание не передано?**  
   — Модуль должен создать задачу с пустым описанием.

2. **Как проверить, что сохранение реально произошло, а не отложено?**  
   — Выключить питание сразу после `createTask`, затем запустить модуль — задача должна быть на месте.

### Сценарий 9 (недопустимый статус)
1. **Что будет, если передать статус "in progress" (с пробелом)?**  
   — Должна быть ошибка, т.к. допустим только `in_progress`.

2. **Что будет, если обновить статус задачи, которая уже имеет этот статус?**  
   — По логике — успех (идемпотентность) или ошибка? Должно быть **успех без изменений**.
