# Требования к модулю «Сервис задач»

## 1. Краткое описание и границы модуля

Модуль предоставляет API для управления задачами студента:
- создание задачи
- изменение статуса задачи
- просмотр списка задач
- поиск по ключевому слову
- сохранение/загрузка в JSON-файл

**Модуль НЕ отвечает за:**
- графический интерфейс или веб-интерфейс
- сетевые взаимодействия (это локальный модуль)
- аутентификацию, роли, права доступа
- уведомления, календари, приоритеты сложнее статуса

## 2. Функциональные требования

1. Модуль должен позволять создать задачу с **названием** (обязательно) и **описанием** (опционально).
2. Модуль должен автоматически назначать задаче **уникальный числовой идентификатор**.
3. Модуль должен позволять изменять статус задачи на один из допустимых: `todo`, `in_progress`, `done`.
4. Модуль должен вернуть ошибку при попытке установить недопустимый статус.
5. Модуль должен возвращать список всех задач.
6. Модуль должен возвращать список задач, отфильтрованных по статусу (возвращает только задачи с указанным статусом).
7. Модуль должен выполнять поиск задач по **ключевому слову** в названии или описании (частичное вхождение, без учёта регистра).
8. Модуль должен позволять редактировать **только статус** задачи. Текст задачи после создания не меняется (ограничение намеренное).
9. Модуль должен сохранять все изменения в файл `tasks.json` после каждой операции создания или изменения статуса.
10. При старте модуль должен загружать данные из `tasks.json`, если файл существует и корректен.
11. При отсутствии файла `tasks.json` модуль должен начать работу с пустым списком задач.
12. При повреждённом JSON-файле модуль должен вернуть ошибку загрузки и начать работу с пустым списком.

## 3. Требования к данным и формату хранения

- Файл хранения: `tasks.json` в корневой папке модуля.
- Кодировка: UTF-8.
- Структура JSON:
```json
{
  "tasks": [
    {
      "id": 1,
      "title": "Купить тетрадь",
      "description": "в клетку, 48 листов",
      "status": "todo"
    }
  ]
}


## 4. Требования по ошибкам и сообщениям

| Ситуация 							    | Ожидаемое поведение 			   | Сообщение об ошибке 				     |
|-------------------------------------------------------------------|----------------------------------------------|---------------------------------------------------------|
| Создание задачи с пустым названием (строка "" или из пробелов)    | Задача не создаётся, возвращается ошибка     | `"Title cannot be empty"`                               |
| Попытка установить недопустимый статус (не todo/in_progress/done) | Статус не меняется, возвращается ошибка      | `"Invalid status. Allowed: todo, in_progress, done"`    |
| Изменение статуса задачи с несуществующим id 			    | Статус не меняется, возвращается ошибка 	   | `"Task with id <id> not found"`                         |
| Повреждённый JSON-файл (невалидный JSON) 			    | Загружается пустой список, ошибка логируется | Лог: `"Corrupted tasks.json, starting with empty list"` |
| Отсутствие JSON-файла при старте 				    | Загружается пустой список 		   | Лог: `"tasks.json not found, starting fresh"`           |
| Попытка создать задачу с названием только из пробелов             | Задача не создаётся, ошибка 		   | `"Title cannot be empty"`       		             |

## 5. Ограничения и допущения

| ID | Ограничение 										     |
|----|-----------------------------------------------------------------------------------------------|
| A1 | Максимальное количество задач не ограничено (кроме доступной памяти)                          |
| A2 | Изменять текст задачи (название или описание) после создания **нельзя** — только статус       |
| A3 | Уникальность задачи определяется только по `id`, названия могут повторяться                   |
| A4 | Поиск выполняется **без учёта регистра** (case-insensitive)                                   |
| A5 | Все операции **синхронные** — результат возвращается сразу 			             |
| A6 | Если при создании задачи описание не передано, оно считается пустой строкой `""`              |
| A7 | При обновлении статуса на тот же самый статус — операция считается успешной (идемпотентность) |
| A8 | Поиск по пустой строке (`""`) возвращает все задачи                                           |

## 6. Критерии приёмки

| № | Критерий 									       | Способ проверки 								       |
|---|----------------------------------------------------------------------------------|---------------------------------------------------------------------------------------|
| PK1 | После создания задача появляется в списке и сохраняется в JSON		       | `createTask("title", "desc")` → `getAllTasks()` содержит задачу; открыть `tasks.json` |
| PK2 | После изменения статуса и перезапуска модуля статус сохраняется 	       | `updateStatus(1, "done")` → перезапуск → статус `"done"`                              |
| PK3 | Попытка создать задачу с пустым названием возвращает ошибку и не меняет список | Ошибка → `getAllTasks()` не изменился 						       |
| PK4 | Поиск находит слово в любом регистре                                           | `findByKeyword("ПРОЕКТ")` → находит `"Проект"`                                        |
| PK5 | При повреждённом JSON модуль стартует без падения и с пустым списком           | Подставить `{"tasks": [` → запуск → `getAllTasks()` пуст                              |
| PK6 | Фильтр по статусу возвращает только задачи с указанным статусом                | У всех задач в результате статус совпадает с фильтром                                 |
| PK7 | Попытка изменить статус на недопустимый не меняет данные                       | Ошибка → статус прежний, файл не изменён                                              |
